# 자차보조금 정산 v6.0 — UX 비교와 검증

검토일: 2026-09-09. 개편 전 기준: `db59e6b` (영수증 금액 인식이 포함된 v6.0 초기 버전). 같은 v6.0의 후속 개선으로 주소 우선 흐름과 한글 타이포그래피를 반영했다. 출장 정보 항목, 정산 규정, 계산 방식과 기존 OCR을 유지한다.

## 핵심 진단

기능은 충분하지만 사용자는 버튼을 누르기 전에 작동 방식을 지나치게 많이 읽어야 했다. 주소 확인과 경로 자동조회가 같은 강도로 경쟁했고, 실제 청구 합계는 계산식에 묻혀 있었다. 조회 결과가 늦게 도착할 때 기다림을 취소할 방법이 없었으며, 처음 방문하자마자 팝업 허용 안내가 작업보다 먼저 보였다. 증빙 가져오기 창은 선택적인 화면 캡처에도 큰 공간을 할당했다.

따라서 색만 줄이기보다 **핵심 결과를 계속 보여주고, 필요한 행동을 분명히 하며, 예외 처리와 선택 기능을 맥락 안에서 제공**하는 것을 우선했다.

## 검증 기록

- `npm run verify`: JavaScript 문법 검사와 Node 테스트. 정산의 45,000개 거리/유가 조합, 소수·절사 경계, 증빙 출처, 중복 사진, OCR 지연과 수동 입력 보존을 포함한다.
- 새 회귀 검증: 합계·증빙 상태, 오류 필드 초점, 경로 취소/즉시 재시도, 주소의 오래된 응답, 유가 캡처 취소, dialog 수명, OCR 대기 중 완료, 닫힌 유가 창의 응답 격리.
- 실제 Chrome 화면: 1440×1000 데스크톱, 390×844·320×740 모바일 크기. 입력과 영수증 창에서 가로 넘침 없음. 하단 합계는 모달과 입력 초점 중 숨겨 방해를 줄인다.
- 운영 검증에서 카카오맵 실제 캡처 1장과 편도 11.3 km → 왕복 22.6 km 반영을 확인했다. 오피넷은 실패 시 조회값 자료로 복구됐으며, 재시도한 실제 PNG에서 ‘처리 중’ GIF가 표를 가리는 문제를 추가 발견했다. 초기 조회·요청한 조회 모두 공식 사이트의 마스크와 진행 창이 사라질 때까지 기다리도록 보완하고 기존 캡처 캐시와 구분했다. 안내를 강제로 지워 완료 화면처럼 만들지 않는다.
- 보완한 코드로 원격 Browser 바인딩에서 2026-09-08 보통휘발유를 다시 캡처했다. 약 20초 후 HTTP 200, 원값 1,859.18원/L을 반환했고, PNG에서 진행 안내 없이 조회 날짜와 표가 온전히 보이는 것을 확인했다. 최종 자동 테스트는 54개다.
- 검증은 합성 입력과 기존 자동 테스트를 사용했다. 새 사용자 모집, A/B 테스트, 실물 iPhone/Safari·Android 키보드 검증은 하지 않았다. 완료 시간 단축률이나 만족도 상승 수치는 주장하지 않는다.

## 남는 제약

웹 캡처는 카카오맵·오피넷의 응답과 화면 구조에 영향을 받는다. 실패 시 거리만 반영하거나 조회값 정리 자료로 대체하는 기존 복구 동작을 유지한다. 취소하면 브라우저에서 결과 반영과 대기를 중지하지만, 서버에서 이미 시작된 캡처 작업은 자체 제한 시간까지 이어질 수 있다. 사진은 브라우저 메모리에만 있으므로 새로고침 전에 정산서를 저장해야 한다.
